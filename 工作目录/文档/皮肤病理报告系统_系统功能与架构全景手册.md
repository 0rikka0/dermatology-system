## 1. 系统概述与设计背景

皮肤病理学是皮肤科临床诊断的“金标准”。在日常诊疗工作中，皮肤病理诊断流程涵盖：临床取材与送检、基本信息录入、组织包埋切片、显微镜观察与摄片、病理医师描述及诊断、特殊免疫组化/疑难会诊标记、上级医师审核质控、报告打印发放及患者签名留档。

传统的文字处理软件或通用医院信息系统（HIS/LIS）常面临如下痛点：
1. **多图排版复杂且易错位**：1 至 9 张显微照片的布局、图注与送检部位对应极易发生页面溢出、表格错位或换行失控。
2. **多院区与病房编号重叠**：门诊、病房（B）、陆港院区（L）、疑难会诊（H）、特殊标本（T）等多前缀编号混杂，容易重号或排序混乱。
3. **质控环节容易遗漏**：疑难“待审核”病例或“免疫组化”未出结果前误打印发放，产生医疗安全隐患。
4. **归档碎片化，检索困难**：照片、录入草稿、终版报告、纸质签领记录分散于不同计算机或目录，追溯困难。

本《皮肤病理报告系统》针对上述行业痛点深度定制研发，集**全流程患者管理、模板智能匹配、显微图像智能排版、严格的多级质控审核锁、一键单页极速打印、签领单自动生成、全景综合检索**于一体，并采用完全自包含的“绿色免安装架构”，无需任何外部网络、依赖库安装或数据库配置，实现即拷即用。

## 2. 总体系统架构与技术栈

系统采用前后端解耦的**本地离线混合架构（Local Native WebUI Architecture）**：

```

|  - 本地快捷操作：Word 外部调用、文件管理器定位、一键静默/专用单页打印           |
+-------------------------------------------------------------------------------+
                                        │ (HTTP REST API / 本地环回 127.0.0.1:8765)
                                        ▼
+-------------------------------------------------------------------------------+
|                            后端应用服务层 (Python 3.11)                       |
|  - FastAPI / Starlette: 轻量级本地异步 API 服务                               |
|  - Uvicorn: 本地 ASGI 服务器                                                  |
|  - Pydantic: 严格的医疗数据字段校验与脱敏格式化                                 |
+-------------------------------------------------------------------------------+
        │                        │                            │
        ▼                        ▼                            ▼
+-----------------+   +----------------------+   +------------------------------+
|   数据持久层    |   |    文档排版引擎      |   |        本地系统调用          |
|  SQLite 3 嵌入  |   |  python-docx / oxml  |   |  Windows Shell 资源管理器    |

+-----------------+   +----------------------+   +------------------------------+
        │                        │                            │
        └────────────────────────┼────────────────────────────┘
                                 ▼
+-------------------------------------------------------------------------------+
|                         本地工作目录与物理文件系统                            |
|  - 统一归档库 (录入草稿、病理输出、显微照片、临床照片、签名单)                 |
|  - 按患者归档库 (一患一夹完整病案包)                                          |

### 核心技术选型特点
- **运行环境纯净**：自带微型嵌入式 Python 运行时环境，零外部组件依赖。
- **排版精准受控**：通过底层 OpenXML 直接注入并精细控制段落行高、表格边框、间距微调，彻底解决多图下文本溢出至第二页的技术难题。
- **系统安全防呆**：严密的文件系统防竞态、防误覆盖机制，配合多重安全确认和状态机拦截。

## 3. 目录存储结构与文件生命周期

本系统对所有医疗文件执行标准化分层归档，在初次启动时由用户选定工作目录根路径（默认或推荐指定为专用大容量数据盘），系统将在该路径下自动初始化标准物理目录树。

### 3.1 目录组织架构树

```
工作目录/
├── 统一归档/
│   ├── 病理报告录入/              # 存放录入初稿 Word 文件 (病理号_姓名.docx)
│   ├── 病理报告输出/              # 存放制作完成、待打印的终稿 Word 报告
│   ├── 病理照片/                  # 存放各病例显微镜拍摄图片 (以“病理号_姓名”建立子文件夹)
│   ├── 临床照片/                  # 存放患者大体/皮损临床照片 (以“患者姓名”建立子文件夹)
│   └── 报告领取签名单/            # 存放生成的每日/指定周期患者签领单 Word 归档文件
├── 按患者归档/                    # 终审完成归档库：一患一夹 (子文件夹：病理号_姓名/)
│   └── [病理号_姓名]/             # 汇集该病例的最终确认报告、病理显微照片等全套资料
├── 特殊患者归档/                  # 疑难/特殊质控病例动态流转中心
│   ├── 待审核/                    # 勾选“待审核”且未完成审核的病例报告
│   ├── 免疫组化/                  # 勾选“免疫组化”且未完成审核的病例报告
│   └── 完成审核/                  # 经审核医师签署并移出的特殊病例报告
├── 模板/                          # 基础排版骨架：1图至9图的标准 Word 模板
├── 文字模板/                      # 描述词库：普通病理描述模板、免疫组化模板
├── 文档/                          # 系统操作手册、逻辑架构规范与运维文档
└── database.db                    # 核心 SQLite 数据库（自动生成于工作目录根）
```

```
   【1. 信息录入】

### 4.2 病理号智能生成与序号流转规则

病理号由系统自动解析与分配，格式高度标准化：
- **无前缀（常规门诊）**：`YYYYMMDD` + `2位流水号`（如 `2026110301`）。
- **带前缀（多院区/特殊标本）**：`前缀字母` + `YYYYMMDD` + `2位流水号`。
  - `B`：住院病房标本（如 `B2026110301`）
  - `L`：陆港/分院区标本（如 `L2026110301`）
  - `H`：疑难院际/科际会诊（如 `H2026110301`）
  - `T`：特检/科研标本（如 `T2026110301`）

**独立递增规则**：不同前缀分类享有完全独立的当日自增计数器。同一天中，`2026110301`、`B2026110301` 与 `L2026110301` 互不干扰，均各自从 `01` 号开始依序递增排列。

## 5. 功能模块全景详解

### 5.1 系统初始化与工作区配置
1. **引导配置向导**：首次启动或工作目录未设定时，系统自动弹出向导模态窗口，引导选择工作目录存储根路径。
2. **医师姓名预设**：用户预置默认“报告医生”与“审核医生”姓名，系统后续录入自动带入，免去重复打字负担。
3. **环境健康度自检**：自动扫描并创建 11 个核心子目录；校验 Word 模板（1-9图模板完整性）及词库文件有效性。

### 5.2 患者信息录入与初稿生成
- **表单化极速输入**：涵盖姓名、性别、年龄、病理号（支持前缀快捷切换）、住院号、门诊号、送检科室/医生、临床诊断、送检部位及病史资料。
- **图片预留位联动**：选择 1 至 9 张图片，界面即刻动态生成对应数量的“送检部位”独立输入框；生成报告时，每个部位将以 `1.部位名称`、`2.部位名称` 规范精确标注在对应显微图片下方。
- **一键生成初稿**：点击【录入并生成报告】，系统自动检索调用对应的 Word 模板，精准注入患者基本信息与部位标识，保存至`统一归档/病理报告录入/`，并自动为该患者在`统一归档/病理照片/`创建专属同名子文件夹，为下一步摄片归集做好准备。

### 5.3 报告制作与排版编辑
- **双栏直观界面**：
  - **左侧工作列表**：实时展示当日（或自选日期）已录入病例，支持按前缀、病理号快速过滤，支持列表内一键选择切换编辑目标。
  - **右侧富编辑台**：分为“病例信息”、“照片装配”、“镜下描述与诊断”、“排版微调与输出”。
- **临床照片跨系统一键调阅**：
  - 界面提供【临床照片查询】按钮。点击后，系统在`统一归档/临床照片/`中匹配“患者姓名”文件夹。
  - 若存在，直接调用 Windows 资源管理器精准定位并打开该文件夹，方便病理医生对照皮损大体表现；若不存在，系统弹出温和提示并打开临床照片总目录供医生手动检索。
- **显微照片装配与替换**：
  - 实时读取显微镜摄片系统输出到`统一归档/病理照片/病理号_姓名/`目录下的图像文件。
  - 界面提供缩略图预览与点选，一键将照片替换至 Word 报告中的预留图片占位符中。
- **智能诊断词库推荐**：
  - 自动识别图像文件名或临床诊断中的关键词（例如识别到“基底细胞癌”或“银屑病”）。
  - 右侧词库栏自动高亮推荐匹配的标准镜下描述模板；医生点击【一键填入】即可将专业描述注入文本编辑框。
  - 支持普通病理与免疫组化模板的分类搜索与快速录入。
- **排版检查与安全保存**：
  - 保存时系统执行排版引擎计算（确保第一页包含完整的医生签名栏与报告日期，第二页仅容纳病史或附页）。
  - 保存文件统一写入`统一归档/病理报告输出/`。

### 5.4 报告审核与特殊病例质控
质控是医疗质量的生命线。本系统构建了严格的**特殊患者质控审核工作流**：
1. **自动拦截归档**：凡勾选“待审核”或“免疫组化”的病例，在报告制作页面**严格禁止直接点击【归档】**。若用户尝试归档，系统自动弹出红色警告，并明确指引进入审核流程。
2. **多队列自动分发**：
   - 制作页保存时，系统自动将报告副本派发至`特殊患者归档/待审核/`和/或`特殊患者归档/免疫组化/`。若两项均勾选，则双队列自动同时入库。
3. **审核工作区独立专责**：
   - 审核医师进入独立的【报告审核】工作区，系统清晰罗列所有处于待审核状态的病例。
   - 审核医师可直接预览 Word、在外部 Word 中批注修正、或核对免疫组化染色结果。
4. **审核通过与物理转移**：
   - 审核医师签署意见并点击【审核通过并归档】后，系统自动将报告从`特殊患者归档/待审核/`与`特殊患者归档/免疫组化/`中移出，整齐归入`特殊患者归档/完成审核/`目录中。
   - 与此同时，自动在`按患者归档/`建立完整病案文件夹，实现双轨闭环归档。

### 5.5 报告输出与批量打印
为防止未审核报告或流转中草稿被误发给患者，【报告输出】工作区实施了精密的**双列表隔离管控体系**：
- **常规报告列表**：展示所有“已归档”且不包含待审核与免疫组化的常规报告。
- **特殊报告列表**：仅展示已勾选待审核/免疫组化，且**已通过上级医师复核（状态为完成审核）**的报告。
- **前缀快速筛选**：支持一键切换“全部”、“普通门诊”、“病房(B)”、“陆港(L)”、“特殊(T)”。
- **一键打印今日归档报告（单页安全打印）**：
  - 系统内置先进的打印调度算法，针对列表中所有今日归档报告，**自动仅打印每份报告的第 1 页**。
  - 彻底规避将第二页冗余的附页病史误打为废纸的问题，大幅节约科室纸张耗材。
- **精细化单病例控制**：针对单份报告，提供“直接预览”、“外部 Word 查看”、“打开归档所在文件夹”、“单份第一页打印”、“撤销归档”、“撤销审核”全套工具链。

### 5.6 报告领取签领单自动化生成
为确保门诊与病房报告交接责任清晰，系统配备独立的【报告领取签名单】工作区：
1. **多维度条件组合**：
   - 支持自由设定报告日期范围（如按日、按周或自定义日期区间）。
   - 支持多前缀复选框灵活勾选（例如同时筛选“病房(B)”和“普通门诊”，或一键全选）。
2. **实时数据表格联动**：
   - 条件变动即时刷新患者清册（显示病理号、姓名、性别、年龄、临床诊断、病理诊断、送检部位、报告医生、报告日期）。
3. **一键生成标准化 Word 签名单并自动打印**：
   - 系统自动生成排版工整的带签收栏 Word 文件（包含“签领人签名”、“签领时间”、“备注”等规范栏目）。
   - 文件自动归档存储至`统一归档/报告领取签名单/签名单_YYYYMMDD_HHMMSS.docx`。
   - 系统支持一键调起打印机，直接将签收单交付前台分发台使用。

### 5.7 病例综合查询与全能维护
- **全要素多重过滤引擎**：
  - 时间范围（支持快捷选择“今日”、“最近3天”、“最近一周”或自定义）。
  - 病理号/住院号/门诊号精确模糊检索、姓名拼音或文字模糊搜索。
  - 病理号前缀（常规/B/L/H/T）快速切片。
  - 归档状态（未归档 / 已归档 / 需要重新归档）与审核状态（待审核 / 完成审核）多重组合。
  - 提供【一键清空重置】功能。
- **全方位运维操作面板**：
  - **快捷修正信息**：修正录入失误（如年龄打错、部位微调）。
  - **跳转二次制作**：一键将选定病例载入报告制作台，重新调整图片或诊断。
  - **穿透式目录定位**：一键展开并唤起 Windows 文件管理器，直接查看“病理报告输出”、“病理照片文件夹”、“按患者归档文件夹”。
  - **强力状态回退保障**：支持受控的“撤销归档”与“撤销审核”，并在数据库与物理磁盘中执行完备的事务性同步。

### 5.8 系统设置与模板维护
- **工作目录一键安全迁移**：支持更换存储盘符或数据迁移，系统自动进行路径合法性与权限验证。
- **医生团队字典维护**：便捷增删或修改报告医生、审核医生预设名单。
- **词库与模板管理入口**：提供直达排版模板与镜下描述词库的物理快捷方式，方便主任与骨干医师随时扩充科室专科词库。

## 6. 排版引擎智能自适应规则

多图排版是皮肤病理报告软件最核心的技术壁垒。本系统通过底层 OpenXML 排版微调算法，构建了严苛的页面动态自适应体系。

### 6.1 各图片规格版面高度与行数补偿基准

报告排版强制锁定：**行距固定为 15 磅（Line Spacing = Exactly 15 pt）**，图片下方部位标注占用 1 行，小标题强制独立占行。系统在保存报告时自动根据图片数量调整行数空白补偿，确保第一页底部正好收于“报告医生 / 审核医生 / 报告日期”署名栏：

| 图片数量类别 | 占用行数与布局形态 | 镜下描述建议可用行数 | 病理诊断建议可用行数 | 页面收尾特征 |
| :--- | :--- | :--- | :--- | :--- |
| **单图 (1张)** | 居中大图展示 (1行) | **14 行** (含标题) | **10 行** (含标题) | 底部无缝贴合署名栏 |
| **双图 (2张)** | 水平双列并排 (1行) | **14 行** (含标题) | **8 行** (含标题) | 底部无缝贴合署名栏 |
| **三图 (3张)** | 上二下一或三图紧凑 | **14 行** (含标题) | **10 行** (含标题) | 底部无缝贴合署名栏 |
| **4 至 6 图** | 双行阵列布局 (2行) | **10 行** (含标题) | **6 行** (含标题) | 自动压缩空行，第一页不分页 |
| **7 至 9 图** | 三行九宫阵列 (3行) | **4 行** (含标题) | **3 行** (含标题) | 极度紧凑排版，首页保全签名 |

### 6.2 版面美化与防错细节
1. **表格边框保护**：
   - 彻底修复了 Word 模板可能出现的添加信息表格底边框缺失问题，强制写入完整底边与外边框。
   - 去除表格上方可能残留的多余浮动横线（VML Shape / Drawing Line），保持文档干练专业。
2. **小标题强制独立占行**：
   - “病理诊断：”小标题后自动执行换行，诊断正文另起一行书写，符合医疗报告国家规范。
   - 图像展示区与“镜下描述：”小标题之间严格保持一个规范标准空行。
3. **占位符智能剥离**：
   - 当用户在制作时选用的图片少于预留位时，系统自动识别并精准剥离多余的空白占位矩形与默认提示字样，重构紧凑表格，严防报告出现空白黑框。

## 7. 安全性、容错与防冲突设计

医疗软件对稳定性和数据安全有近乎苛刻的要求。系统在底层实现了一整套完备的防冲突体系：

### 7.1 “需要重新归档”保护机制（防静默数据漂移）
- **现象**：某病例已归档入库后，如果医生在制作工作区再次打开并修改了病理诊断并点击保存。
- **机制**：
  - 制作界面的保存**仅覆盖更新**`统一归档/病理报告输出/`中的工作副本。
  - 制作界面的保存**严禁直接静默覆盖**`按患者归档/`和`特殊患者归档/`中已封存的历史病案。
  - 系统立即将数据库中该病例的状态置为**“需要重新归档”**。
  - 只有在操作者明确点击【重新归档】按钮后，才将最新成果同步覆盖归档库，杜绝意外篡改已交付病案。
  - *例外原则*：在【报告审核】工作区中，由质控主任执行的保存为最高质控指令，直接具备全目录同步更新权限。

### 7.2 智能防重号与重名防覆盖
- 患者姓名相同时，系统以带日期与序号的病理号作为全局主键和目录物理名（`病理号_姓名`），彻底防止同名同姓患者的资料互相覆盖。
- 病理号自增在 SQLite 中使用独占事务计算，并发写入时自动加锁，杜绝生成重复病理号。

### 7.3 文件占用与异常熔断处理
- 在调用 Word 或执行打印时，若目标文件正被其他第三方软件独占打开，系统具备友好的异常捕获机制，提示操作者关闭 Word 进程，而绝不引起后台服务崩溃或静默丢失修改。

## 8. 绿色免安装部署与离线运行规范

为确保在医院内网隔离机房、病理科切片电脑及医生工作站上无需任何 IT 运维人员协助即可快速开箱即用，系统采用全封装绿色离线运行模式。

### 8.1 交付包目录结构
```
皮肤病理报告系统-绿色免安装版/
├── 运行系统.bat                 # 一键主启动脚本（双击即自动唤起服务并打开浏览器）
├── 停止系统.bat                 # 优雅安全退出与后台进程守护释放脚本
├── runtime/                     # 内置全套便携式 Python 3.11 运行环境
├── app/                         # 系统核心源码包与业务模块
├── static/                      # 本地 Web 前端资源（CSS、JS、图标、离线库）
├── 模板/                        # 初始标准 Word 排版模板
├── 文字模板/                    # 初始标准病理诊断词库
├── 工作目录/                    # 初始预置规范工作区（含文档手册）
└── dist/                        # 自动化绿色发布包存储库
```

### 8.2 快速使用三步法
1. **解压**：将分发的 `皮肤病理报告系统-绿色免安装版.zip` 解压至任意磁盘（推荐 `D:\` 或 `E:\` 根目录）。
2. **启动**：直接双击运行根目录下的 `启动系统.bat`。系统将自动启动本地服务并调起默认浏览器访问 `http://127.0.0.1:8765`。
3. **初始化**：在首次打开的网页中确认工作目录路径与医生姓名，即可立即开展日常病理报告录入与出具工作。
4. **退出**：工作结束后，直接双击 `停止系统.bat` 即可完整、安全地关闭所有本地后台常驻服务。
