## 1. 系统概述与设计背景

皮肤组织病理学是皮肤病临床诊疗的重要依据。皮肤科病理日常作业涉及临床取材送检、患者登记与病理号编排、组织切片与显微镜摄片、病理描述与诊断模板套用、疑难/重切病例上级审核、后续独立免疫组化（IHC）报告出具、法定单页纸质报告打印及患者领取签收等全流程闭环。

**皮肤病理报告系统（v6.0）** 采用“零外部依赖本地原生 WebUI + Python 内置微服务端 + SQLite 双表持久化 + 分层文件系统隔离”架构，全部运行环境与依赖均可离线打包，解压即用，同时针对临床科室高频痛点构建了 **OS 级单实例无感防多开**、**双草稿双向同步质控**、**独立免疫组化双报告并行**、**外部 Word 修改自动检测与三层隔离双向同步**、**防静默永久删除与数据库容灾快照** 以及 **15 磅固定行距单页打印保护** 机制。

## 3. 目录存储结构与三轨生命周期

### 3.1 程序运行目录与工作目录边界

程序运行根目录存放源码/运行时与临时状态文件，业务数据全部严格限定在用户设定的**工作目录**内：

- **程序目录运行时文件**：
  - `config.json`：系统初始化状态与偏好配置；
  - `.server_runtime.json`：当前运行中后台服务的临时元数据（`app_id`、`pid`、`port`、`url`、`started_at`），正常退出、调用 `/api/system/exit` 或 `停止系统` 时自动清理；强杀残留会在下次启动获取互斥体后自动覆盖清理。
- **工作目录标准拓扑**：

```text
工作目录/
├── 未归档报告/                    # 日常制作与流转工作区
│   ├── 病理报告录入/              # 录入阶段生成的初稿 (病理号_姓名.docx)
│   ├── 病理报告输出/              # 制作与审核区共享的成品草稿 (病理号_姓名_诊断.docx)
│   ├── 病理照片/                  # 显微镜拍摄图片文件夹 (病理号_姓名/)
│   └── 临床照片/                  # 唯一临床照片源目录 (制作/审核/组化临床查询均直开此目录)
├── 已归档报告/                    # 最终成品单文件平铺库 (无子目录、不复制照片、零冗余膨胀)
│   ├── 2026110301_张建国_皮内痣.docx               # 原初诊报告归档文件
│   └── 2026110301_张建国_皮内痣_免疫组化报告.docx   # 同患者第二份独立免疫组化归档文件
├── 特殊患者归档/                  # 特殊流程独立目录（仅复制病理照片，绝不复制临床照片）
│   ├── 待审核/                    # 标记“待审核”病例的同步草稿包 (含 [病理报告]...docx 与 病理照片/)
│   ├── 重切/                      # 标记“需重切”病例的同步草稿包 (处理逻辑与 待审核 完全等价)
│   ├── 完成审核/                  # 待审核/重切经完成审核并在制作区归档后的完整留存包
│   └── 免疫组化/                  # 【免疫组化】模块创建后的独立草稿与组化病理照片目录
├── 领取表/                        # 批量生成的签名单 (.xlsx 与 .docx)
└── 数据库/                        # pathology.db (WAL 主库) 与 backups/ (最新 20 份快照轮转)
```

### 3.2 核心业务三轨生命周期

```text
【轨道 A：常规病例 ＆ 仅标注“需免疫组化”患者的原初诊报告】（未勾选 待审核/需重切）
   录入建档 ─► 制作保存 (未归档报告/病理报告输出) ─► 制作区【一键归档 / 今日批量归档】─► 已归档报告/<文件名>.docx
   * 说明：仅勾选“需免疫组化”视同普通患者流转，允许直接归档与首页打印；保存时不自动创建 特殊患者归档/免疫组化。

【轨道 B：待审核 / 重切病例（二者处理逻辑完全等价）】
   制作保存 (勾选待审核和/或需重切) ─┬─► 写入「未归档报告/病理报告输出/病理号_姓名_诊断.docx」
                                    └─► 复制病理照片(无临床照) + 草稿 ─►「特殊患者归档/待审核(或重切)/」
                                             │
                                             ▼ (两份草稿双向等价同步)
   报告审核区 (仅显示待审核/重切) ───────────┼─► 临床查询直开「未归档报告/临床照片」；病理照片用复制后目录
                                             ├─► 【保存修改并同步草稿】：回同步新增照片 + 同步刷新两份草稿，不动已归档
                                             ├─► 【一键打印第一页】：保存同步后立即调用 Word COM 仅打第 1 页
                                             └─► 【完成审核】：状态置为“完成审核”
                                             │
                                             ▼
   返回【报告制作】点击【一键归档】 ─────────┼─► 移动 待审核/重切 ─►「特殊患者归档/完成审核/」
                                             └─► 写入或更新「已归档报告/病理号_姓名_诊断.docx」
   * 说明：对此前已归档病例在审核区保存修改后，archived 自动置 2（需重新归档），同样须回制作区确认归档后才更新 已归档报告/。

【轨道 C：独立免疫组化报告流程（同一患者的第二份独立报告）】
   进入 🧪【免疫组化】 ─► 点击【创建免疫组化报告】(强制校验原报告已在 已归档报告/)
        │
        ├─► 复制「已归档报告/<原文件名>.docx」 + 「未归档报告/病理照片/」(不复制临床照片)
        │   生成于「特殊患者归档/免疫组化/<原归档stem>/」
        ├─► 独立编辑医生/日期/镜下描述/诊断/照片（支持打开/复制组化照片夹、临床照片查询）
        ├─► 【保存免疫组化报告】：仅更新「特殊患者归档/免疫组化/」与 ihc_reports 表，绝不动原报告与 patients 主表
        ├─► 【归档免疫组化报告】：仅将 .docx 存入「已归档报告/<原文件名>_免疫组化报告.docx」
        │   (与原报告并存不覆盖；不移动 特殊患者归档/免疫组化/，不放入 完成审核/)
        └─► 【删除免疫组化报告】(可选)：将组化目录与 *_免疫组化报告.docx 移入回收站，清空 ihc_reports 并清除
            patients.is_needs_ihc 与 review_status 中的“免疫组化”标识（原报告完整保留）
```

### 4.2 独立免疫组化报告副表（`ihc_reports`）

### 4.3 归档状态机与重归档守卫

- **`archived = 0 ➔ 1`**：常规或完成审核患者首次通过【一键归档】或【批量归档】入 `已归档报告/`。
- **`archived = 1 ➔ 2`（需要重新归档）**：
  - 在【患者信息录入】修改此前已归档（`archived in (1, 2)`）患者的信息；
  - 在【报告制作】重新保存已归档报告；
  - 在【报告审核】保存修改已归档报告（严禁审核保存直接改写 `已归档报告/`）。
- **未归档患者修改信息免弹窗守卫**：若修改对象本身 `archived == 0`，更新后仍保持 `archived = 0`，后端返回 `ask_rearchive = false`，不弹“是否立即重新归档”提示。

## 5. 八大核心功能模块全景详解

WebUI 顶部导航依次排列八大工作区：`📝 患者信息录入`、`🔬 报告制作`、`⚖️ 报告审核`、`🧪 免疫组化`、`🖨️ 报告输出`、`📋 报告领取签名单`、`🔍 病历综合查询`、`⚙️ 系统设置`。

### 5.1 系统初始化与合规免责弹窗
- 每次进入 WebUI 均弹出不可跳过的**免责声明与风险提示**窗：点击【我已知晓并同意】进入作业；点击【退出】触发 `/api/system/exit` 关闭后台进程。
- 首次运行弹出设置向导，初始化工作目录并核验 `模板/` 与 `文字模板/` 完整性。

### 5.2 患者信息录入（Entry）
- **多前缀独立流水号**：无前缀（普通门诊报告）、`B`（病房报告）、`L`（分院区门诊报告）、`H`（会诊报告）、`T`（其他特殊报告），各前缀当日编号从 `01` 独立递增；切换前缀或送检日期自动继承并预览下一号；
- **弹性信息录入**：年龄下拉选择 `岁/月/日` 并支持 `自由输入`（兼容如 `1岁3月` 儿童患者）；`H`/`T` 前缀开放送检单位与科室编辑；1–9 图动态联动送检部位输入框；
- **列表筛选与路径直达**：支持按报告日期、送检日期与关键词筛选，按病理号正序展示；支持选中患者一键【📷 临床照片查询】。

### 5.3 报告制作（Report Making）
- **排队与色卡区分**：默认按病理号正序排列，以不同底色清晰区分未保存、已制作、已归档、待审核、重切、需免疫组化及“完成审核待重归档”；
- **今日一键批量归档**：【📦 一键归档今日已保存未归档报告】自动筛选今日已保存输出且未标注待审/重切的报告（含普通及纯免疫组化），展示确认清单后批量归档入库；
- **采图与词库引擎**：支持【📷 临床照片查询】、【📂 打开病理照片文件夹】、【📋 复制病理照片路径】及【📄 空白报告模板】；自动解析显微图文件名合成诊断（单图自动去序号、多图保留序号），结合 249 篇内置模板实现智能置顶推荐与弹窗覆盖/追加写入；
- **特殊分流判定**：仅勾选 `需免疫组化` 按常规流程流转；勾选 `待审核` 或 `需重切` 则在制作区禁用直接归档，转入审核协同闭环。

### 5.4 报告审核（Report Review）
- **队列范围**：仅展示 `待审核` 与 `重切` 病例（二者完全等价），支持报告/送检日期、关键词检索及“显示已完成审核患者”切换；
- **目录精准分离**：【临床照片查询】直达 `未归档报告/临床照片/`；【病理照片目录】与【复制路径】指向 `特殊患者归档/待审核(或重切)/<患者目录>/病理照片/`，放入复核/重切照片后点【重新读取照片】即可装配；
- **双向同步与审核打印**：支持修改报告医生、审核医生、报告日期、照片、描述与诊断；提供【保存修改并同步草稿】与【🖨️ 一键打印第一页】（保存同步并即刻打印首页）；点击【✅ 完成审核】后返回【报告制作】一键归档并移入 `完成审核/`。

### 5.5 独立免疫组化（IHC Workspace）
- **强前置校验**：必须患者原报告已归档于 `已归档报告/` 方可点击【创建免疫组化报告】；
- **独立编辑与目录复制**：提供复制后组化照片目录打开/路径复制、【📷 临床照片查询】、医生/日期/镜下所见/诊断编辑；
- **独立保存、归档与红色删除**：【保存】只写 `特殊患者归档/免疫组化/` 与 `ihc_reports`；【归档】只写 `已归档报告/<原名>_免疫组化报告.docx`；【🗑️ 删除免疫组化报告】将误建组化报告与目录安全移入回收站并清除患者组化标记，恢复常规状态而不损伤原报告。

### 5.6 报告输出三列表（Report Output）
- 物理三栏并列展示：**常规已归档报告**、**特殊审核完成报告**、**免疫组化已归档报告**；
- 均支持送检/报告日期范围、多前缀复选过滤、高保真预览、Word 打开、文件定位、单独/批量调用 Word COM 仅打第 1 页，以及互不干扰的【撤销归档】/【撤销审核】。

### 5.7 报告领取签名单（Signing Sheet）
- 支持按送检或报告日期范围及多前缀筛选候选病例，一键同步生成无空行 Word 签名单与 Excel 签名单存至 `领取表/`；

### 5.8 病历综合查询（Search）与系统设置（Settings）
- 综合查询默认时间范围设为“全部时间”，支持**报告日期区间**与**送检日期区间**双日期过滤、前缀、归档状态、审核状态及多号码关键词检索；支持查看关联全部路径（含独立组化路径）、跳转修改/制作、状态受控更新及回收站彻底删除；
- 系统设置支持工作目录迁移、默认医生持久化与模板文件夹一键直达。

1. 根据当前页面有效版心宽度与表 0 宽度测算右侧右对齐制表位极限位置；
2. 优先保持 `12pt` 宋体与标准制表位间距；若医生姓名字数较长导致右侧溢出，先紧凑调整左制表位偏移，若仍超出则按 `0.5pt` 步长自适应微缩字号（最低 `9.0pt`），从排版层面彻底保证签名栏恒定单行且不跨页。

- **Win10 / Win11 主分支**：通过 PowerShell 调用 `Word.Application`（或 `KWPS.Application` / `wps.Application`），在 `page1_only=True` 时以 `wdPrintFromTo`（`Range=3, From='1', To='1'`）精确打印第 1 页，完全跳过第 2 页病史附页，同时内置无 `[ref]` 位置参数降级分支兼容 WPS。
- **Windows 7 专版隔离**：严禁使用 PowerShell 3.0+ 的 `ConvertFrom-Json`/`ConvertTo-Json`，改用临时 UTF-8 文件传递与 `.NET 2.0` 原生 `ReadAllLines`/`WriteAllText` 交互，所有 COM `[ref]` 参数显式强转为 `[object]` 并轮询 `$app.BackgroundPrintingStatus`（上限 10 秒）防退出丢单，通过 `_decode_win_output` 按 `utf-8-sig`/`utf-8`/`gbk`/`cp936` 解码报错信息。

### 6.4 外部 Word 逆向解析与富文本/批注就地保留机制（v6.0 新增）

- **全量结构化逆向解析（`extract_docx_details`）**：采用强引用 `cell._tc` 去重准确提取 `tables[0]` 12 项元信息（自动兼容 `YYYY-MM-DD` 与中文日期）、`tables[1]` 1–9 图编号送检部位、多行 `镜下描述：` / `病理诊断：` / `病史：` 及签名栏（报告医生、审核医生、报告日期）。

## 7. 单实例防多开、并发安全与容错设计

### 7.1 四重“无感防多开 + 单图标进入”架构

为解决 `启动系统(无黑框后台版).vbs` 后台运行期间，用户关闭浏览器后再次双击图标导致悄悄多开 `pythonw.exe` 进程的问题，系统构建了四重协同防多开机制：

```text
用户双击「启动系统(无黑框后台版).vbs」
        │
        ▼
[1] pythonw.exe 极速入口 (main.py 顶层，未加载 docx/openpyxl 前)
    调用 Win32 CreateMutexW("Local\DermatologySystem_Instance_Lock")
        │
        ├──► 若互斥体已存在 (GetLastError == 183 / 5)：
        │      ├─► 轮询读取 .server_runtime.json 取得 actual_port (缺失则扫描 port..port+9)
        │      ├─► 强制 ProxyHandler({}) 绕过系统代理 GET http://127.0.0.1:{port}/api/status
        │      ├─► 校验响应 JSON 含 app_id == "dermatology-system"
        │      └─► 直接唤起浏览器打开该地址 (Win7 优先现代浏览器) 并静默退出 (sys.exit(0))
        │
        └──► 若成功获得互斥体 (首个实例)：
               ├─► 清理可能存在的崩溃残留 .server_runtime.json
               ├─► 启动 ThreadedHTTPServer：allow_reuse_address=False + SO_EXCLUSIVEADDRUSE
               ├─► 自动顺延可用端口 (8765~8774)，写入原子更新的 .server_runtime.json
               ├─► log_message 增加 sys.stdout is not None 空流防护
               └─► 启动服务并弹出浏览器；退出时自动清理状态文件并释放内核句柄
```

- **核查安全停止（`python -m app.instance_lock --stop`）**：先通过 `/api/status` 确认目标服务真实身份与 PID，优先发 `POST /api/system/exit` 优雅关停并 `WaitForSingleObject` 等待退出；超时未退则通过 Win32 `TerminateProcess` 结束指定 PID；若 HTTP 已无响应但状态文件残留，先通过 `QueryFullProcessImageNameW` 与 `netstat` 校验该 PID 确为监听于目标端口的 `python.exe`/`pythonw.exe` 后才介入，彻底杜绝 PID 复用误杀。

### 7.2 数据、文件安全删除与容灾快照体系

1. **排他写入锁探测**：生成或覆盖 Word 报告、Excel 签名单或执行删除/归档前执行 `_ensure_writable` 探测；若文件正被 Word/WPS 打开占用，主动拦截并返回 `HTTP 409` 中文指引。
2. **SQLite 并发与 20 份 WAL 一致性快照轮转**：数据库统一启用 `PRAGMA journal_mode=WAL`、`synchronous=NORMAL` 与 `busy_timeout=15000`；每日首次启动及每次执行 `delete_patient()` 前均调用 `sqlite3.Connection.backup()` 在 `数据库/backups/` 生成时间戳快照，自动按时间轮转留存最新 **20 份**（过期备份通过回收站清理）。
3. **防静默永久删除与覆写前先回收**：`safe_delete_path()` 优先调用打包内置的 `send2trash` 并回退至无 `shell=True` 参数列表化 PowerShell（20s 超时）；当网络共享路径等导致两者均失败时，拒绝静默调用永久删除，转而抛出 `RecycleBinFailedError` 返回 `HTTP 409`（`confirm_permanent: true`），待用户二次确认后附带 `force_permanent` 方可继续。全部 Word/Excel 写入与归档前均调用 `backup_before_overwrite()` 先将旧版本送入回收站；`/api/ihc/create` 新建前禁止静默覆写已有组化草稿。
4. **改名防冲突与主键唯一归档清理**：`rename_patient_files_and_folders()` 借助 `_move_path_safe()` 在移动前先检查目标冲突并回收旧目标，支持 Windows 大小写重命名并拒绝静默吞错；所有归档检索与清理统一采用 `_matches_patient_no()` 主键匹配并结合历史路径清理，确保改名、改号（含延迟重归档）后 `已归档报告/` 永不遗留旧名残留文件，且始终绝不触碰 `未归档报告/临床照片/`。

### 7.3 外部 Word 修改检测与三层级隔离协同（v6.0 新增）

1. **SHA-256 指纹比对与遗留零误报**：系统生成或写入报告后记录规范化路径与哈希至 `doc_sync_meta`；检查时自动跳过 Word `~$` 锁文件，且对历史空 `doc_sync_meta` 患者保持静默不误报。
2. **非打扰提示与强冲突阻断**：列表接口仅附带轻量化外改徽章（`⚠️ Word已外改`）；用户在点击选中患者、打开编辑/预览/首页打印，或触发写入覆写 `HTTP 409`（`EXTERNAL_MODIFIED_CONFLICT`）拦截时，通过浏览器原生 `window.confirm()` 选择 **正向导入** 或 **移入回收站备份后反写覆盖**（正向导入成功后对于表单编辑页不再回写覆盖旧框值）。
3. **三层级隔离边界**：录入层导入不覆盖下游已写诊断与描述；草稿层（输出/待审核/重切/完成审核）同级保留样式分发并置 `archived=2`，不动录入层与成品层；已归档层（含原报告与组化已归档）外部修改确认导入后直接更新数据库与归档命名，保持 `archived=1` 不污染上游草稿、不复催重归档；组化与普通报告仅跨文档同步基本公共信息，外部 Word 病理号不匹配以 `409 PATHOLOGY_NO_MISMATCH` 强制拦截。
