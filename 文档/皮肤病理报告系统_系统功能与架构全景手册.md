## 1. 系统概述与设计背景

皮肤病理学是皮肤科临床诊断的“金标准”。在日常诊疗工作中，皮肤病理诊断流程涵盖：临床取材与送检、基本信息录入、组织包埋切片、显微镜观察与摄片、病理医师描述及诊断、上级医师对“待审核/重切”病例的复核质控、后续“免疫组化”加做与第二份独立组化报告出具、报告单页打印发放及患者签收留档。

本《皮肤病理报告系统》针对医院皮肤科病理业务痛点深度定制研发，集**全流程患者管理、1-9 图智能排版、待审核/重切双向草稿同步质控、独立免疫组化双报告机制、Word COM 一键仅打第 1 页、Excel + Word 签领单自动生成、全景综合检索**于一体，并采用完全自包含的“绿色免安装架构”（含 Windows 10/11 与 Windows 7 专版），实现离线解压即用。

### 核心技术选型特点
- **轻量嵌入式运行时**：自带便携式 Python 3.8 运行时及纯净依赖轮子（`python-docx`、`lxml`、`openpyxl`、`et_xmlfile`），不写入系统注册表、不依赖互联网。
- **排版精准受控**：通过底层 OpenXML 注入控制表格边框、清除多余 VML 线条并锁定 15 磅行距，确保 1-9 图报告均以第一页医生签名栏精确收尾。
- **独立双报告隔离架构**：`patients` 与 `ihc_reports` 双表物理分离，常规/审核报告与后续免疫组化报告相互独立编辑、保存、归档、预览、打印与撤档，互不覆盖。

## 3. 目录存储结构与文件生命周期

初次启动由用户指定**工作目录**根路径后，系统自动初始化标准子目录（技术与操作文档位于软件根目录 `文档/`，运行工作目录保持业务数据纯净）：

### 3.1 目录组织架构树

```
工作目录/
├── 未归档报告/                    # 日常制作与流转工作区
│   ├── 病理报告录入/              # 录入阶段生成的初稿 (病理号_姓名.docx)
│   ├── 病理报告输出/              # 制作与审核区共享的成品草稿 (病理号_姓名_诊断.docx)
│   ├── 病理照片/                  # 显微镜拍摄图片文件夹 (病理号_姓名/)
│   └── 临床照片/                  # 患者大体皮损照片目录 (制作与审核临床查询均直接打开此目录)
├── 已归档报告/                    # 最终成品单文件平铺库 (无子文件夹、不复制照片、零冗余膨胀)
│   ├── 2026110301_张建国_诊断.docx                # 原初诊报告归档文件
│   └── 2026110301_张建国_诊断_免疫组化报告.docx    # 同患者第二份免疫组化报告归档文件（如已做组化）
├── 特殊患者归档/                  # 特殊流程独立目录（仅复制病理照片，不复制临床照片）
│   ├── 待审核/                    # 标记“待审核”病例的同步草稿包 (含 [病理报告]...docx 与 病理照片/)
│   ├── 重切/                      # 标记“重切”病例的同步草稿包 (处理逻辑与 待审核 完全等价)
│   ├── 完成审核/                  # 待审核/重切经完成审核且一键归档后的完整留存包
│   └── 免疫组化/                  # 【免疫组化】模块主动创建后的独立报告草稿与组化病理照片目录
├── 领取表/                        # 按送检/报告日期生成报告领取签名单 (.xlsx 与 .docx)
└── 数据库/                        # 存放 pathology.db SQLite 主数据库及 WAL 日志文件
```

### 3.2 核心业务三轨生命周期

```
【轨道 A：常规病例 ＆ 仅标注“需免疫组化”患者的原报告】（无待审核/重切）
   录入建档 ─► 制作保存 (未归档报告/病理报告输出) ─► 制作区【一键归档】─► 已归档报告/<文件名>.docx
   * 说明：仅标注“需免疫组化”视同普通患者，可在制作区直接归档和打印；保存时不生成 特殊患者归档/免疫组化。

【轨道 B：待审核 / 重切病例（二者处理逻辑完全等价）】
   制作保存 (勾选待审核或重切) ─┬─► 写入「未归档报告/病理报告输出/病理号_姓名_诊断.docx」
                              └─► 复制病理照片(不复制临床照片)+草稿 ─►「特殊患者归档/待审核(或重切)/」
                                       │
                                       ▼ (两份草稿双向等价同步)
   报告审核区 (仅显示待审核/重切) ──────┼─► 临床查询看「未归档报告/临床照片」；病理照片用复制后目录
                                       ├─► 【保存修改并同步草稿】：同步更新上述两份草稿与同步新增照片，不动已归档
                                       └─► 【完成审核】：状态置为“完成审核” (待归档/重归档)
                                       │
                                       ▼
   返回【报告制作】点击【一键归档】 ────┼─► 移动 待审核/重切 ─►「特殊患者归档/完成审核/」
                                       └─► 同步写入「已归档报告/病理号_姓名_诊断.docx」
   * 说明：若已归档病例在审核区被再次修改保存，archived 自动置 2（需重新归档），同样须回制作区归档才更新 已归档报告/。

【轨道 C：独立免疫组化报告流程（已归档原报告基础上产生第二份新报告）】
   进入 🧪【免疫组化】 ─► 点击【创建免疫组化报告】(校验原报告已在已归档报告/)
        │
        ├─► 复制「已归档报告/<原文件名>.docx」 + 「未归档报告/病理照片/」 (不复制临床照片)
        │   生成于「特殊患者归档/免疫组化/<原归档stem>/」
        ├─► 独立编辑医生/日期/镜下描述/诊断/照片（一键打开或复制免疫组化照片目录录入染色图）
        ├─► 【保存免疫组化报告】：仅更新「特殊患者归档/免疫组化/」与 ihc_reports 表，不动原报告与 patients 表
        └─► 【归档免疫组化报告】：仅将 .docx 存入「已归档报告/<原文件名>_免疫组化报告.docx」
            (与原报告并存，不覆盖原报告；不移动 特殊患者归档/免疫组化/，不放入 完成审核/)
```

## 4. 核心数据模型与状态机设计

系统使用 SQLite 3（开启 `WAL` 预写日志与 `busy_timeout = 15000`），通过 `patients` 主表与 `ihc_reports` 副表分别维护原报告和独立免疫组化报告生命周期。

### 4.3 病理号智能生成与序号流转规则

- **无前缀（常规门诊）**：`YYYYMMDD` + `2位流水号`（如 `2026110301`）。
- **带前缀（多院区/特殊标本）**：`前缀字母` + `YYYYMMDD` + `2位流水号`（`B` 病房、`L` 分院区、`H` 会诊、`T` 特检）。
- **独立递增规则**：各前缀当日计数相互独立，均从 `01` 开始递增，以带前缀的完整字符串作为全局主键。

## 5. 功能模块全景详解

系统 WebUI 顶部设有 **8 大核心工作区**：`📝 患者信息录入`、`🎨 报告制作`、`⚖️ 报告审核`、`🧪 免疫组化`、`🖨️ 报告输出`、`📋 报告领取签名单`、`🔍 病历综合查询`、`⚙️ 系统设置`。

### 5.1 系统初始化与工作区配置
1. **启动免责声明拦截**：每次打开 WebUI 自动弹出风险提示与执业复核免责窗，支持【我已知晓并同意】或【退出】（触发 `/api/system/exit` 终止后台进程）。
2. **引导向导与目录自检**：首次运行引导设定工作目录及默认报告/审核医生，自动建立全套规范目录并校验 Word 模板与词库文件。

### 5.2 患者信息录入与初稿生成
- 支持前缀独立取号、儿童年龄（下拉 `岁/月/日` 及 `自由输入` 如 `1岁3月`）、`H/T` 前缀自定义送检单位与科室、1-9 图动态送检部位联动。
- 支持今日患者列表按**报告日期 / 送检日期 / 关键词**过滤及病理号正序排列，支持直接点击【📷 临床照片查询】。
- **修改同步与重归档询问**：修改已保存/已归档患者信息后，自动级联更新数据库、草稿、输出文件、`特殊患者归档`（含待审核/重切/完成审核/免疫组化副本）目录与内容，**严禁直接改动 `已归档报告/`**；如非待审挂起状态则弹窗询问是否立即重新归档。

### 5.3 报告制作与特殊标注分流
- **列表与状态底色**：按病理号正序展示列表，以独立底色区分已保存、已归档、待审核、需免疫组化、重切及“完成审核未归档（需重新归档）”。
- **照片装配与词库推荐**：自动读取 `未归档报告/病理照片/病理号_姓名/`，按命名合成诊断（单图去序号，多图保留序号）；内置 249 篇模板支持智能置顶推荐与弹窗覆盖/追加填入。
- **特殊标注分流（核心规则）**：
  - **`待审核` / `需重切`（完全等价）**：保存时同步更新 `未归档报告/病理报告输出/` 与 `特殊患者归档/待审核/`（或 `重切/`），仅复制病理照片（不复制临床照片）；制作区点击【一键归档】会被拦截，提示完成审核后再归档。
  - **`需免疫组化`**：仅标注“需免疫组化”的病例视作常规病例处理，制作保存**不会**生成 `特殊患者归档/免疫组化/`，可直接在制作区归档和打印第 1 页；若同时勾选 `待审核`/`重切`，则两者逻辑同时生效（归档受待审约束）。

### 5.4 报告审核工作区（待审核与重切）
- **队列筛选**：仅列示 `待审核` 与 `重切` 患者（支持报告日期、送检日期、关键词检索及“显示已完成审核患者”切换）。
- **照片功能分工**：
  - **临床照片查询（`#btn-rev-find-clinical`）**：打开 `工作目录/未归档报告/临床照片/` 中对应患者文件夹，不依赖特殊归档副本；
  - **病理照片目录打开与复制（`#btn-rev-open-photo-dir` / `#btn-rev-copy-photo-path` / 路径栏）**：直接指向复制后的 `工作目录/特殊患者归档/待审核（或重切）/<患者目录>/病理照片/`；审核区【重新读取照片】扫描该复制目录。
- **编辑保存与双向草稿同步**：
  - 支持编辑报告医生、审核医生、报告日期、照片插槽、镜下描述与病理诊断；
  - 保存修改时自动将审核目录新放入的照片同步回 `未归档报告/病理照片/`（以及同患者的兄弟队列目录），并**同时覆盖更新** `未归档报告/病理报告输出/` 与 `特殊患者归档/(待审核 | 重切 | 完成审核)/` 两份草稿，保证两处完全一致、视同同一份报告（在报告制作区修改保存也会反向同步至特殊归档草稿）；
  - 审核保存**不直接改动 `已归档报告/`**。若此前已归档，保存后数据库自动置 `archived = 2`（需重新归档）。
- **完成审核与归档闭环**：审核无误点击【✅ 完成审核】；之后前往【报告制作】点击【📦 一键归档】，将原报告写入 `已归档报告/` 并将待审目录移入 `特殊患者归档/完成审核/`。

### 5.5 独立免疫组化工作区（IHC）
为满足“原初诊报告先按常规出片归档、后续免疫组化再出具第二份独立报告”的临床场景，系统设立独立的 `🧪 免疫组化` 工作区：
1. **队列展示**：展示所有标注 `需免疫组化` 或已创建组化副本的患者，列表筛选布局与审核模块一致。
2. **创建免疫组化报告（`POST /api/ihc/create`）**：
   - **前置条件**：患者原报告必须已归档至 `工作目录/已归档报告/`，否则拦截并提示先完成原报告归档；
   - **复制范围**：复制原已归档 `.docx` 与 `未归档报告/病理照片/` 至 `工作目录/特殊患者归档/免疫组化/<原归档文件名stem>/`（**绝不复制临床照片**）。
3. **独立编辑与照片路径助手**：
   - 可独立修改免疫组化报告医生、审核医生、报告日期、照片插槽（仅读取复制后的组化 `病理照片/` 目录）、镜下所见（支持词库弹窗与推荐模板）与免疫组化病理诊断；
   - 提供一键打开复制后组化病理照片目录与一键复制目录路径按钮，方便特染照片录入，同时提供“临床照片查询”直接查看 `未归档报告/临床照片/`。
4. **独立保存与独立归档**：
   - **保存（`POST /api/ihc/save`）**：仅写入 `特殊患者归档/免疫组化/` 内的 `.docx` 与 `ihc_reports` 表，**不改动 `patients` 主表及原报告（未归档与已归档原件均原封不动）**；若该组化报告此前已归档则将 `ihc_reports.archived` 置为 `2`。
   - **归档（`POST /api/ihc/archive`）**：仅将保存后的免疫组化 `.docx` 复制归档到 `工作目录/已归档报告/<原已归档文件名stem>_免疫组化报告.docx`，与原报告在 `已归档报告/` 中独立并存；**不移动 `特殊患者归档/免疫组化/` 目录，不进入 `完成审核/`**。

### 5.6 报告输出三列表与批量单页打印
【报告输出】采用 **三列表物理隔离**，所有打印与批量打印按钮均统一调用 Word/WPS COM 引擎 **仅打印第 1 页**：
1. **📋 常规已归档报告**：包含普通报告，以及仅标注“需免疫组化”并按常规归档的原初诊报告。
2. **🛡️ 特殊审核完成报告（待审/重切+完成审核）**：仅展示经审核完成后正式归档的原报告，支持“撤销归档”与“撤销审核”。
3. **🧪 免疫组化已归档报告**：展示已独立归档的 `*_免疫组化报告.docx`；支持按日期与前缀筛选、独立预览、在 Word 中打开、定位归档文件、单独/批量打印第 1 页，以及**独立撤销组化归档**（撤档仅移除 `*_免疫组化报告.docx`，保留原报告与 `特殊患者归档/免疫组化/` 目录）。

### 5.7 报告领取签领单自动化生成
- 支持按**送检日期**或**报告日期**区间及多前缀（普通 / B / L / T）联合筛选候选病例。
- 一键同步生成 **Excel + 无空行 Word** 签名单并存入 `领取表/`；Word 签名单标注送检日期及参考手术日期（前一工作日推算），【打印签名单】直接调用 Word 打印。

### 5.8 病例综合查询与全能维护
- 支持按送检日期、前缀、归档状态（未归档 / 已归档 / 需重新归档）、审核状态（含 `免疫组化` / `重切` / `待审核` / `完成审核`）及姓名/病案号组合检索。
- 结果支持穿透定位全部关联文件与目录（新增独立展示 `特殊患者归档 (免疫组化)` 与 `已归档免疫组化报告`）、跳转制作、受控状态变更与回收站安全彻底删除。

### 5.9 系统设置与模板维护
- 支持工作目录迁移、默认医生配置、排版模板与 249 篇文字模板文件夹直达维护。

## 7. 安全性、容错与防冲突设计

1. **“需要重新归档”防静默覆盖机制**：
   - 在录入修改基本信息、制作台重保存已归档报告，或**在【报告审核】对已归档报告保存修改**时，均不静默改动 `已归档报告/`，而是将归档状态置为 `2`（需重新归档），要求经办人于【报告制作】核验后点击【一键归档】正式刷新封存档案；
   - 独立免疫组化报告修改已归档副本时同理将 `ihc_reports.archived` 置为 `2`，由【免疫组化】模块主动重归档。
2. **双草稿＆双报告文件边界隔离**：
   - 审核模块 `未归档报告/病理报告输出/` 与 `特殊患者归档/(待审核 | 重切 | 完成审核)/` **互为镜像草稿**，审核增补照片与制作修改双向同步；
   - 免疫组化模块 `特殊患者归档/免疫组化/` 与 `已归档报告/*_免疫组化报告.docx` **与原报告严格隔离**，常规与审核的保存、归档、撤档均排除 `*_免疫组化报告.docx` 与 `特殊患者归档/免疫组化/`。
3. **并发、排他锁与软删除保护**：
   - 保存 Word 或 Excel 前执行写入排他探测（`_ensure_writable` / `generate_report_file`），若被 Word/WPS 占用则拦截并返回 HTTP 409 中文提示；
   - Word COM 打印隔离超时回收 `WINWORD.EXE`；SQLite 开启 `WAL + busy_timeout=15000`；所有删除动作调用 Shell 安全移入 Windows 回收站。
