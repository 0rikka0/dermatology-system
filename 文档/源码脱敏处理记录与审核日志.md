## 1. 脱敏背景与原则

为确保软件在 GitHub 等开源平台公开发布时，杜绝泄露任何实际医疗机构、特定分院区名称、医护人员真实执业身份、临床患者就诊隐私及本地构建环境信息，项目每次向 GitHub 同步前均执行**全要素、深层穿透式脱敏专项治理**：

### 核心脱敏原则：
1. **真实医疗机构 100% 擦除**：替换为通用示范型代称（如“某三甲医院皮肤科”）。
2. **分院区特征名称 100% 泛化**：将特定分院区字样统一替换为“分院区 / 分院”。
3. **医护人员姓名 100% 替换**：替换为符合医疗角色的假名代称（报告医师统一为“张医生”，审核医师统一为“李主任”，送检医师统一为“王医生”）。
4. **患者病例数据 100% 模拟**：示例报告与文档中的姓名、病案号、门诊号、送检部位均转换为合成虚拟数据。
5. **Office 二进制元数据 100% 清理**：Word/Excel 的 `docProps/core.xml` 中的 `dc:creator`（创建者）、`cp:lastModifiedBy`（修改者）全部重置为泛化标识 `DermatologySystem`，擦除个人操作系统用户名。
6. **开源仓库边界严格隔离**：`export_staging` 仅同步 GitHub 既有仓库范围内的开源文件，绝不上传本地私有运行库、构建产物（`dist/`、独立兼容分支打包物）或未纳入仓库的本地脚本。

## 3. v6.0 同步更新与脱敏核查清单

1. **后端核心模块（`app/` & `main.py`）**：
   - 更新 `app/path_manager.py`、`app/database.py`、`app/doc_preview.py`、`app/doc_generator.py`、`app/server.py`、`app/signing_sheet_generator.py`：引入安全防静默永久删除（`RecycleBinFailedError` + 打包 `Send2Trash`）、覆写前回收备份（`backup_before_overwrite`）、数据库 20 份 WAL 快照轮转、外部 Word SHA-256 检测与三层隔离双向同步、就地样式批注保留、以及主键唯一归档机制；全程无机构、医生或患者隐私信息残留；
   - 保持通用命名与实例锁（`Local\DermatologySystem_Instance_Lock` / `dermatology-system`）。
2. **前端与测试（`web/`、`scripts/` & `tests/`）**：
   - 更新 `web/index.html`、`web/css/style.css`、`web/js/app.js` 并将医生占位值及分院区标签脱敏；
   - 更新 `scripts/build_standalone_package.py` 与 `scripts/generate_manual_pdf.py`，同步补全 `Send2Trash` 依赖校验与最新五类前缀规范表（无前缀=普通门诊报告、B=病房报告、L=分院区门诊报告、H=会诊报告、T=其他特殊报告）；
   - 保持 GitHub 既有的 `tests/test_fixes_and_enhancements.py`、`tests/test_phase2.py`、`tests/test_phase3.py` 与 `requirements.txt` 脱敏一致。
3. **文档与 SOP 图文手册（`README.md`、`CHANGELOG.md`、`文档/`）**：
   - `README.md` 与 `CHANGELOG.md` 完善 `v1.0` 至 `v6.0` 大版本演进、安全防删与外部 Word 双向同步说明；
   - `文档/皮肤病理报告系统_系统功能与架构全景手册.md` 与 `文档/系统逻辑设计与冲突梳理说明.md` 升级至 v6.0（涵盖 18 大核心冲突梳理及五类前缀标准定义），全文采用脱敏示例数据；
   - `文档/皮肤病理报告系统_快速入门操作手册.pdf` 更新 v6.0 SOP 与最新病理号前缀速查表，内嵌截图全部在脱敏环境与纯虚拟病例下生成。
4. **排除项**：
   - 严格排除本地私有适配分支、构建产物（`dist/`、`runtime/`）、运行配置文件（`config.json`、`*.db`、`.server_runtime.json`）及未纳入 GitHub 仓库的本地测试与开发辅助文件。
