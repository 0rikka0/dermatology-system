## 1. 脱敏背景与原则

为确保软件在 GitHub 等开源平台公开发布时，杜绝泄露任何实际医疗机构、特定分院区名称、医护人员真实执业身份、临床患者就诊隐私及本地构建环境信息，项目每次向 GitHub 同步前均执行**全要素、深层穿透式脱敏专项治理**：

### 核心脱敏原则：
1. **真实医疗机构 100% 擦除**：替换为通用示范型代称（如“某三甲医院皮肤科”）。
2. **分院区特征名称 100% 泛化**：将特定分院区字样统一替换为“分院区 / 分院”。
3. **医护人员姓名 100% 替换**：替换为符合医疗角色的假名代称（报告医师统一为“张医生”，审核医师统一为“李主任”，送检医师统一为“王医生”）。
4. **患者病例数据 100% 模拟**：示例报告与文档中的姓名、病案号、门诊号、送检部位均转换为合成虚拟数据。
5. **Office 二进制元数据 100% 清理**：Word/Excel 的 `docProps/core.xml` 中的 `dc:creator`（创建者）、`cp:lastModifiedBy`（修改者）全部重置为泛化标识 `DermatologySystem`，擦除个人操作系统用户名。
6. **开源仓库边界严格隔离**：`export_staging` 仅同步 GitHub 既有仓库范围内的开源文件（及必要的 `app/instance_lock.py`、`CHANGELOG.md`），绝不上传本地私有运行库、构建产物（`dist/`、`win7/`、`win7.zip`）或未纳入仓库的本地脚本。

## 3. v5.0 同步更新与脱敏核查清单

1. **后端与单实例锁模块（`app/` & `main.py`）**：
   - 新增 `app/instance_lock.py`（纯通用命名 `Local\DermatologySystem_Instance_Lock` 与 `dermatology-system`，不含任何机构或个人标识）；
   - 更新 `main.py`、`app/server.py`、`app/database.py`、`app/doc_generator.py`、`app/path_manager.py`、`app/signing_sheet_generator.py` 并全量执行文本敏感词替换；
2. **前端与测试（`web/` & `tests/`）**：
   - 更新 `web/index.html`、`web/css/style.css`、`web/js/app.js` 并将医生占位值及分院区标签脱敏；
   - 保持 GitHub 既有的 `tests/test_fixes_and_enhancements.py`、`tests/test_phase2.py`、`tests/test_phase3.py` 脱敏一致；
3. **文档与 SOP 图文手册（`README.md`、`CHANGELOG.md`、`文档/`）**：
   - `README.md` 与 `CHANGELOG.md` 完善 v1.0 至 v5.0 版本演进与防多开说明；
   - `文档/皮肤病理报告系统_系统功能与架构全景手册.md` 与 `文档/系统逻辑设计与冲突梳理说明.md` 升级至 v5.0，全文采用脱敏示例数据；
   - `文档/皮肤病理报告系统_快速入门操作手册.pdf` 内嵌的实景 WebUI 标注截图全部在脱敏环境与纯虚拟病例下现场生成，无任何真实机构或患者信息。
4. **排除项**：
   - 严格排除 `win7/`、`win7.md`、`win7.zip`、`dist/`、`runtime/`、`config.json`、`*.db`、`.server_runtime.json` 及本地未纳入 GitHub 仓库的其他文件。
